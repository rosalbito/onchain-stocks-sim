Matching is sequential: message 41 must go before 42. A second thread can’t make it faster, only make the two take turns through a lock.

Incrementing one 64-bit counter 500 million times · LMAX Disruptor technical paper, §2.1 · bar length on a log scale

This is why the engine has exactly one writer thread, the design LMAX used to run an exchange on a single thread. The only shared thing in this benchmark is one counter, and adding a lock and a second thread made it about 750 times slower. Everything around the book (parsing, validation, the dashboard) runs on other threads and talks to the engine through lock-free ring buffers.
